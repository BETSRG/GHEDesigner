# Graphical input editor

Launch the local editor after installing GHEDesigner:

```bash
ghedesigner-gui
```

The command starts a service on the local computer and opens it in the default browser. Use `--no-browser` to suppress
automatic opening, `--port` to select a port, or `--host` to select a network interface.

The service writes a rotating diagnostic log to `~/.ghedesigner/gui.log` and prints the resolved path at startup. The
log includes request identifiers and timings, validation timings, example loads, browser exceptions, failed requests,
and detected browser event-loop stalls. It retains three 5 MB backups. Use `--debug-log` for successful browser events
and detailed validation timings, or `--log-file PATH` to select another location. When reporting an apparent hang,
include the log section from `session_started` through the stalled interaction.

The editor can open, validate, save, and export ordinary version 4 GHEDesigner JSON files. Guided forms cover fluid,
soil, simulation controls, and every field of each physical component. Component collections are edited one item at a
time so variant-heavy GHE schemas remain responsive; changes are staged until **Apply section** or **Apply component**
is selected. A complete guarded raw JSON view remains available for final review.

Guided forms display the schema's natural-language `title` for every field, including engineering-specific names such
as **Design flow per borehole** and **Volumetric heat capacity**. Exported JSON and the raw JSON view continue to use
the canonical machine-readable property names, so changing a display label never changes the input-file format.
The seasonal ground-temperature model appears last in the Soil form only when horizontal heat transfer is enabled and
at least one horizontal-piping component makes the model necessary.
Every load-file path includes a **Browse…** button that opens the operating system's file chooser on the computer
running `ghedesigner-gui`; the path remains directly editable when a relative or not-yet-created path is preferred.

## Workflow modes

The start page and persistent selector above the editor distinguish five execution paths: standalone GHE design,
g-function calculation, one-building/one-GHE design, district-system sizing, and district-system simulation with
pre-designed GHEs. Opening an existing input selects the matching workflow automatically. The selected workflow is an
editor concern and is not stored as non-schema metadata in the exported JSON.

The sidebar and forms show only inputs consumed by the selected path. Heat pump performance and horizontal-piping tabs
appear when their corresponding simulation-control switches require them. Sizing workflows expose geometry, design
limits, and search controls, while simulation and g-function workflows expose pre-designed borefield geometry.
Workflow readiness checks supplement JSON schema and topology validation so an incomplete but structurally valid draft
cannot be run or exported.

## Network editing

Compact one-pipe and two-pipe inputs use an ordered station editor. It controls station order, distribution segments,
pipe defaults, and the one-pipe distribution flow rule. One-pipe station bypasses are generated automatically as
zero-loss paths. A read-only canonical preview shows the internal node/branch representation that the solver receives;
this representation is generated by GHEDesigner and is not an additional input mode.

## Validation and export

Schema and topology validation run while the document is edited. Diagnostics include the JSON pointer, source, and
suggested corrections. Drafts may be saved at any time; export is enabled only when the document is valid. The editor
also prevents a simulation from starting until these diagnostics are resolved.

## Running a simulation

Select **Run simulation** at the bottom of the sidebar, enter the output directory on the computer running the GUI or
use **Browse…** to select it, and then select **Run simulation**. Relative output paths are resolved from the directory where `ghedesigner-gui` was
launched. The run executes in a separate process so the editor remains responsive. The page shows the current status,
elapsed time, process output, exit status, and resolved output path; an active run can be cancelled. Only one simulation
can run from a GUI process at a time.

The editor executes the current in-memory input, including changes that have not been saved as a JSON file. Paths in
load-file fields should therefore be absolute when running an input opened through the browser.

## Frontend development

The frontend source is in `ghedesigner/gui/frontend`. Install its JavaScript dependencies and build the packaged static
assets with:

```bash
cd ghedesigner/gui/frontend
pnpm install
pnpm build
```

For live development, run `pnpm dev` and launch the Python service on port 5055 with
`ghedesigner-gui --no-browser --port 5055`.
